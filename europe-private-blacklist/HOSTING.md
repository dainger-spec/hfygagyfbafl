# Europe Private Blacklist — хостинг

Нужен Node 20+.

## ВАЖНО: папка `data` на сервере

В `data/` лежат список чатов с рассылкой (`telegram-bindings.json`,
`telegram-relay-chats.json`), заявки, ID и доказательства. Файлы `data/` в
репозитории — только стартовые; рабочие данные живут на сервере.

- **Никогда не удаляйте и не заменяйте `data/` на сервере.**
- Перед каждым обновлением скачайте `data/` себе — это резервная копия.
- Бот сам делает ежедневные копии в `data/backups/` (30 дней).
- Раз в сутки бот присылает владельцу в личку файл `epb-backup-ДАТА.json.gz` —
  копию всех данных (кроме сессии юзербота и файлов доказательств/баннеров).
  Она переживёт даже пропажу сервера. Прислать сразу: команда `/backup`
  владельцу в личке бота.

### Восстановление из копии из Telegram

1. Остановите бота.
2. Положите файл `epb-backup-ДАТА.json.gz` на сервер.
3. `node scripts/restore-backup.mjs epb-backup-ДАТА.json.gz`
   (текущие файлы сначала сохранятся в `data/backups/before-restore-…/`).
4. Запустите бота.

## Обновление

1. Скачайте себе копию папки `data/` с сервера.
2. Остановите приложение.
3. Удалите на сервере папку `.output` и файл `dist-output.tgz`. Больше ничего не удаляйте.
4. Залейте файлы из этой папки (`dist-output.tgz`, `package.json`, `scripts/`, `public/`, `vite.config.mjs`, `HOSTING.md`).
5. В `.env` или в панели хоста:

```
TELEGRAM_BOT_TOKEN=ваш_токен
PUBLIC_URL=https://europe.bothost.tech
PORT=3000
DATA_DIR=./data
```

6. `npm run build`
7. `npm start`

После смены токена ничего дополнительно делать не нужно.

### Как бот получает сообщения (устойчивость к DDoS)

По умолчанию бот сам забирает обновления у Telegram (long polling) и не ждёт
входящих запросов на домен. Поэтому если домен мини-аппа недоступен (DDoS,
проблемы прокси или DNS), бот продолжает отвечать — нужен только исходящий
доступ сервера к api.telegram.org. Мини-апп при этом, конечно, не откроется.

Запускайте только одну копию приложения: две копии с одним токеном мешают друг
другу. Вернуть старый режим (Telegram сам шлёт запросы на
`/api/telegram/webhook`): `TELEGRAM_UPDATES=webhook`.

Защита на уровне кода (от атак запросами; от забивания канала спасает только
сеть — датацентр или Cloudflare):

- более 500 запросов за 10 секунд с одного IP — ответ 429 на минуту (порог: `EPB_FLOOD_MAX`). Если хостинг не передаёт настоящий IP посетителя (все запросы приходят с внутреннего адреса прокси), этот лимит не применяется, чтобы не заблокировать всех сразу — остаётся защита по общей нагрузке;
- если сервер начинает не успевать, лишние запросы сразу получают 503: сначала
  самые активные адреса, при сильной перегрузке — все, кроме Telegram. Бот в
  том же процессе продолжает работать;
- медленные соединения (заголовки по байту) обрываются, тела запросов больше
  3 МБ не принимаются;
- адрес посетителя берётся из `X-Forwarded-For` / `CF-Connecting-IP` только если
  соединение пришло от прокси хостинга (внутренние адреса) или от Cloudflare.
  Подставив чужой адрес в заголовок, обойти лимит нельзя. Свой прокси с
  внешним адресом добавляется в `EPB_TRUSTED_PROXIES=1.2.3.0/24,…`;
- главная страница одинакова для всех, поэтому хранится в памяти 3 секунды
  (`EPB_HOME_CACHE_MS`). Флуд главной отдаётся из памяти без рендера, в том
  числе при перегрузке;
- запросы сканеров уязвимостей (`.php`, `.env`, `.git`, `wp-…` и т.п.) сразу
  получают 404 и считаются за 25 обычных: такой адрес быстро блокируется;
- с одного адреса не больше 64 открытых соединений одновременно
  (`EPB_CONN_PER_IP`) и не больше 200 запросов на одно соединение;
- запросы Telegram на вебхук без лимитов, но только с секретом бота. Чужие
  запросы на этот адрес ограничиваются как обычные.

### Быстрый поиск по каналам (локальная копия)

Юзербот в фоне копирует всю историю каналов проверки и канала EPB (чтобы
находились и посты, написанные админами вручную, а не через бота) в `data/check-mirror/`
(один файл на канал) и раз в минуту докачивает новые посты, раз в 6 часов
перечитывает последние ~300 постов (правки и удаления). Поиск идёт по копии —
доли секунды, вся история. Пока канал докачивается, для него дополнительно
работает обычный поиск Telegram. Сколько уже скачано: `/userbot` (владельцу в
личке: размер базы, проверенные пары username → ID, по каждому каналу — «вся
история» или «~N%»), а также `/usearch @username`. Новый канал начинает
копироваться сразу после добавления. Папку можно удалить: копия
соберётся заново. В резервную копию в Telegram она не входит.

### Карточка аккаунта в проверке

Над результатом проверки показывается, что известно об аккаунте: ID (из
Telegram, а если ник уже никому не принадлежит — из постов блеклистов), имя,
отметки Telegram SCAM/FAKE и ограничения, Premium, фото профиля, когда был в
сети, «О себе» и личный канал, примерная дата регистрации и возраст (оценка по
ID, Telegram её не сообщает), когда впервые появился в блеклистах и ранее
известные ники. Всё, кроме «О себе»/канала, приходит в ответе на поиск по нику,
который бот делает и так; «О себе» — один дополнительный запрос, не чаще раза в
сутки на аккаунт и с отдельным лимитом. Дата регистрации считается локально.

Для своего MTProto-входа бот берёт ваши API ID/HASH (те, что введены для
юзербота, или `TELEGRAM_API_ID`/`TELEGRAM_API_HASH`), а не ключи официального
приложения. Историю ников Telegram тоже не
отдаёт: бот собирает её сам в `data/telegram-username-history.json` (всё, что
он видел) и берёт пары «ник — ID» из постов блеклистов. Прежние ники тоже
ищутся по копиям каналов.

### Строки в логе

- `[epb] HTTP guards on` — при запуске: защита от частых запросов включена.
- `[epb] userbot FLOOD_WAIT 7s` — Telegram попросил юзербот подождать N секунд
  между поисками. Норма: бот сам выжидает, поиски в это время ждут очереди.
- `[epb] polling: …` — бот временно не может забрать сообщения у Telegram
  (нет сети, неверный токен или запущены две копии). Он повторяет сам.

### Свой домен за Cloudflare (защита от DDoS)

Для поддомена `*.bothost.tech` Cloudflare подключить нельзя. Порядок для своего домена:

1. Добавить домен в Cloudflare (бесплатный тариф).
2. A-запись на IP ноды бота (узнать в поддержке Bothost), прокси включён
   («оранжевое облако»), SSL/TLS — Full.
3. Привязать домен к боту в панели Bothost.
4. В `.env` поставить `PUBLIC_URL=https://ваш-домен` и перезапустить. Кнопку
   мини-аппа в боте бот обновит сам. Если в BotFather задан «Main Mini App» или
   ссылка мини-аппа со старым адресом — поменять её там на новый.

Настоящий IP посетителя за Cloudflare бот берёт из `CF-Connecting-IP`, так что
ограничение частых запросов работает правильно.

5. Когда домен уже работает через Cloudflare, поставить в `.env`
   `EPB_CLOUDFLARE_ONLY=1` и перезапустить. Соединения не от Cloudflare (и не от
   прокси хостинга) сервер сразу обрывает. Даже если атакующий узнает IP
   сервера, обойти Cloudflare и бить напрямую он не сможет. Боту это не мешает:
   с Telegram он общается сам, исходящими запросами. Не включайте это, пока
   домен не за Cloudflare: мини-апп перестанет открываться.

## Команды в чате судей

- `/admin` — панель управления на кнопках: сводка (в т.ч. «База блеклиста: ~N
  аккаунтов» — сколько аккаунтов находит проверка контрагента, и прогресс, пока
  каналы докачиваются), заявки без решения, чаты рассылки (включить/выключить,
  проверить права бота), канал для постов. Аккаунта поиска (юзербота) и списка
  каналов-источников в `/admin` нет: в чате судей их не видно, ими управляет
  только владелец через `/userbot`
- `/relays` — список чатов рассылки
- `/relay_on -100…` — включить рассылку в чат вручную
- `/relay_off -100…` — выключить
- `/channel -100…` — сменить канал для постов

## Публикация заявки

1. «Опубликовать» → появятся кнопки «С рассылкой», «Без рассылки»,
   «✏ Изменить текст», «👁 Предпросмотр».
2. «✏ Изменить текст» → ответьте на сообщение бота новым текстом поста
   (жирный, курсив, ссылки сохраняются). Строки с аккаунтом/суммой и подпись
   Subscribe бот добавит сам. «↩ Вернуть исходный текст» отменяет правку.
3. Пост публикуется в канал (`/channel` или панель → «Канал для постов»),
   а в чаты рассылки бот пересылает уже пост из канала. Если в канале включена
   защита от пересылки, бот отправит в чаты копии.

## Удаление блеклиста во всех чатах

`/admin` → «🗑 Удалить блеклист»: список опубликованных записей. Выберите
запись → бот покажет подтверждение → «🗑 Да, удалить везде». Бот удалит пост
из канала и все разосланные копии/пересылки во всех чатах рассылки, а запись
пропадёт из канала и из поиска (проверки контрагента).

- Удаление необратимо.
- Telegram не даёт боту удалять сообщения старше 48 часов в обычных чатах, где
  он не админ с правом удаления. Такие сообщения останутся — бот честно покажет,
  сколько удалил и сколько не смог.
- Работает только для записей, разосланных уже после установки этого обновления
  (бот запоминает ID разосланных сообщений в момент рассылки).

## Баннеры в мини-аппе

`/admin` → «🖼 Баннеры»: баннеры показываются сверху в мини-аппе (можно листать,
если их несколько). Видео и GIF проигрываются без звука и по кругу, тап по
баннеру открывает ссылку.

1. «➕ Добавить баннер» → пришлите боту картинку, видео или GIF (до 20 МБ).
2. Затем пришлите ссылку (`https://…` или `t.me/…`), которая откроется по тапу.
   Если ссылка не нужна — отправьте «-».
3. Чтобы удалить баннер — нажмите на него в списке (🗑). До 20 баннеров.

Медиа баннеров хранится в `data/banners/` — это часть `data/`, не удаляйте её.

## Рассылка пользователям бота

`/admin` → «📣 Рассылка пользователям бота»: количество пользователей и рассылка
только им в личные сообщения (в чаты и каналы она не уходит).

1. «✉ Новая рассылка» → ответьте на сообщение бота тем, что нужно разослать:
   текст, фото, видео, GIF, стикер или альбом, с форматированием.
   Премиум-эмодзи сохранятся, если у владельца бота есть Telegram Premium.
   Не удаляйте это сообщение до конца рассылки — бот копирует именно его.
2. Бот покажет предпросмотр. «➕ Добавить кнопки» → ответьте строками
   `Текст - https://ссылка`, кнопки в одном ряду через `|`.
3. «🚀 Разослать» → «✅ Да, разослать». Прогресс обновляется в чате, есть
   кнопка «⏹ Остановить». После перезапуска сервера рассылка продолжится,
   повторно никому не отправит.

## Проверка контрагента и юзербот (для владельца)

В мини-приложении есть «Проверка контрагента»: поиск по @username / ссылке / ID.
Показываются только одобренные жалобы EPB, выложенные в канал (удалённые и тестовые
не показываются), и совпадения в выбранных каналах через подключённый аккаунт.

На странице проверки также выводятся «Недавние блеклисты». Тап по блеклисту
открывает карточку прямо в приложении: описание ситуации, ущерб, дата. Для
записей, добавленных вручную, карточка показывает «Информация взята из стороннего
источника. Оспорить — @EuropePromo» и кнопку, открывающую t.me/EuropePromo.

Подключение аккаунта делает владелец бота прямо в личке с ботом:
1. Напишите боту `/userbot` (работает только для владельца).
2. «Подключить аккаунт» → пришлите api_id и api_hash (my.telegram.org), телефон, код
   из Telegram и, если есть, пароль двухфакторной защиты.
3. «📡 Выбрать из подписок» → отметьте каналы, по которым искать (аккаунт должен
   быть на них подписан), или «➕ Добавить по @/ID». Убрать канал — кнопка «🗑»
   с его названием. Поиск идёт по username, нику и ID, включая старые посты.
В той же панели `/userbot` — статус аккаунта, размер базы и сколько скопировано по
каждому каналу («🔄 Обновить» перерисовывает цифры).
Отмена входа: `/cancel_userbot`. Сессия хранится в `data/user-session.txt` — держите
папку `data` закрытой, лучше заведите для этого отдельный аккаунт.

### Добавить юзера в блеклист вручную

`/admin` → «➕ Добавить юзера в блеклист»: пришлите `@username` или ID, можно с
комментарием через пробел (например, `@scammer инфа из чужого блеклиста`). Запись
появится в проверке контрагента с источником **«Сторонний источник»**. Так можно
занести скамера без полной жалобы — например, по данным из другого блеклиста.

### Убрать юзера из блеклиста (поиска)

`/admin` → «🧹 Убрать юзера из блеклиста»: пришлите `@username`, ID или номер
жалобы `EPB-…`. Все подходящие жалобы и ручные записи перестанут находиться в
проверке контрагента (жалобы в истории остаются). Пост в канале при этом не
трогается — чтобы удалить его и копии везде, используйте «🗑 Удалить блеклист».

### Включение/выключение проверки контрагента

По умолчанию проверка контрагента ВКЛЮЧЕНА (кнопка «Проверка контрагента» в
мини-аппе, строка базы и кнопки блеклиста в `/admin`). Скрыть: владелец пишет боту в личку `/checkoff`
(вернуть — `/checkon`). Либо на хосте задайте `EPB_CHECK_ENABLED=0`.

## Премиум-эмодзи в боте

В личных сообщениях бот ставит премиум-эмодзи из пака владельца: шаги жалобы,
меню, капча, карточка аккаунта и проверка контрагента (✅ чисто, ⛔ найдено,
⏳ проверяем, ▫️ в очереди). Недостающие значки бот сам находит в паке
(по уже используемому значку узнаёт имя пака и читает его целиком) и хранит
неделю в `telegram-bindings.json`. Команды владельца в личке: `/emoji` — статус,
`/emoji on|off`, `/emoji reload` — перечитать пак и показать, какие значки взяты.
Если Telegram откажет в кастомных эмодзи, сообщение уйдёт с обычными.

Проверка в боте показывается одним сообщением, которое меняется примерно раз в
секунду: полоса прогресса, источники берутся в работу по очереди, затем по
порядку открываются результаты и итог «Найдено в N из M» / «Чисто во всех».

## Работа под большой нагрузкой

- Поиск по копиям каналов идёт по словарю ников и ID (строится в фоне после
  запуска), поэтому даже сотни одновременных проверок занимают доли секунды.
  Поиск по нику с пробелом («Dark Money») просматривает копию целиком.
- Одинаковые проверки, пришедшие одновременно, выполняются один раз.
- Одновременно идёт не больше 4 просмотров копий; остальные ждут очереди,
  бот при этом продолжает отвечать.
- Анимация проверки в боте замедляется, когда много людей проверяют разом, а при
  40+ одновременных проверках показывается сразу результат (у Telegram общий
  лимит ~30 сообщений в секунду на бота).
- Размер базы считается в фоне небольшими порциями и обновляется раз в минуту.
- История поиска (`/admin` → «🔍 История поиска», последние 10) и языки
  пользователей записываются на диск с задержкой в несколько секунд, а не на
  каждый запрос.
- Фото постов, открытых в приложении, хранятся в `data/post-media` (не больше
  40 МБ, старые удаляются сами). Папку можно удалить — фото скачаются заново
  при следующем открытии.
- Память: копии каналов держатся в памяти вместе со словарём. Ориентир —
  ~1,5 КБ на пост (10 000 постов ≈ 15 МБ, 260 000 ≈ 400 МБ).

### Если мини-апп грузится медленно

Раз в минуту, когда запросов много или кто-то отсечён, в логе появляется строка:

```
[epb] http last minute: 714 requests, 429: 200, 503: 0, 413: 0, max lag 56 ms, max in flight 4, busiest address 198.51.100.7 (501/10s)
```

- много `429` и один «busiest address» с сотнями запросов — флуд/DDoS с адреса(ов),
  защита его отсекает;
- `503` — сервер перегружен и временно отказывает (сброс нагрузки);
- `max lag` больше ~500 ms — занят сам процесс;
- строки нет или цифры обычные, а страницы всё равно открываются медленно —
  тормозит сеть/прокси хостинга (bothost), а не приложение. Бот при этом работает,
  потому что сам ходит к Telegram, а не принимает входящие запросы.

### Проверка участников чата (/pars)

Владелец бота пишет `/pars` в любом чате, где есть бот. В чате появляется одна
тихая строка «Продолжите в личных сообщениях бота» (через минуту она и сама
команда удаляются), дальше всё идёт в личке.

- Юзербота нет в чате — бот создаёт одноразовую ссылку (на 1 человека, 10 минут),
  юзербот вступает, после проверки выходит. Боту нужно право «Пригласительные ссылки».
- Список участников скрыт настройками чата — юзербот на время проверки получает
  одно право «Управление чатом» (оно открывает список и больше ничего не меняет),
  после проверки право снимается. Боту нужно право «Назначение администраторов».
- Служебные сообщения «вступил / вышел» юзербота бот удаляет (если у него есть
  право удалять сообщения). Если сервер перезапустился посреди проверки, после
  старта бот сам снимет право и выведет юзербота.

Юзербот выгружает участников страницами по 200 с паузой ~1,5–2 с (Telegram отдаёт
до 10 000 человек), только читает. Участники сверяются с локальной базой (жалобы
EPB, копии каналов, ручной список), лишних запросов на каждого человека нет.
Одновременно идёт одна проверка, один и тот же чат — не чаще раза в 10 минут.
Отчёт с найденными и ссылками приходит владельцу в личку (при многих находках — ещё
и файлом).
